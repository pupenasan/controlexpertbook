# Кібербезпека

## Системний вигляд

Наступна архітектура підкреслює необхідність використання багаторівневої архітектури з мережею керування (Control Network) та мережею пристроїв (Device Network), яка може бути більш захищеною. Плоска архітектура, в якій усе обладнання під’єднане до однієї мережі, не може бути належним чином захищена.

![image-20250816192322324](C:\san\Навч посіб M340\GitVer\uk2\media\image-20250816192322324.png)

Обладнання в операторській кімнаті (Control Room) більш вразливе до атак, ніж обладнання, підключене до мережі пристроїв. Тому слід реалізувати більш захищені комунікації між операторською кімнатою та контролером і пристроями. Ізолюйте мережу пристроїв від інших рівнів мережі (таких як мережі керування та віддалені мережі).

В архітектурі системи вище зона операторської кімнати позначена сірим кольором, щоб відрізнити її від контролера та інших пристроїв.

Фізичний доступ до USB-портів необхідно контролювати. Захист USB-портів може бути здійснений лише фізичними засобами (наприклад, шафа чи фізичний ключ).

Контролюйте фізичний доступ до з’єднання Hot Standby та до мережі пристроїв.

Control Expert надає симулятор для тестування вашого застосунку перед введенням його в експлуатацію як частини вашої системи промислової автоматизації. Симулятор відповідає вимогам кібербезпеки:

- Симулятор може працювати лише з відкритим застосунком у Control Expert.
- Застосунок, відкритий у симуляторі, не може бути завантажений із симулятора до контролера.

## Setting Passwords in Control Expert

Використовуйте програмне забезпечення Control Expert для встановлення паролів, які допомагають захистити ваш проєкт. Можна встановити такі паролі:

- Пароль застосунку, з шифруванням файлу або без нього
- Пароль для області, пов’язаної з безпекою
- Пароль для оновлення прошивки
- Пароль для програмного блоку, секції та підпрограми
- Пароль для сховища даних/веб-доступу

Control Expert надає механізм пароля, щоб допомогти захиститися від несанкціонованого доступу до застосунку. Control Expert використовує пароль, коли ви:

- відкриваєте застосунок у Control Expert
- підключаєтесь до контролера в Control Expert

### Пароль для області, пов’язаної з безпекою

Контролери безпеки містять функцію захисту паролем для області, пов’язаної з безпекою, яка доступна з екрана властивостей проєкту. Ця функція використовується для захисту елементів проєкту, розташованих у зоні функціональної безпеки. Коли функція активна, частини застосунку, пов’язані з безпекою, не можуть бути змінені. 

![image-20250816194520587](C:\san\Навч посіб M340\GitVer\uk2\media\image-20250816194520587.png)

Для доступу в `maintenance mode` необхідно ввести пароль; якщо не ввести його протягом 5 хвилин — контролер переходить у *safety mode*.

Пароль блокує будь-які зміни в безпечних частинах проєкту, шифрується за SHA-256 і є обов’язковим механізмом захисту для нових версій прошивки та Control Expert. 

### Пароль застосунку

Захист застосунку паролем допомагає запобігти небажаним змінам застосунку, його завантаженню чи відкриттю файлів застосунку. Пароль зберігається в застосунку у зашифрованому вигляді. Крім захисту паролем можна зашифрувати файли `.STU`, `.STA` та `.ZEF`. Функція шифрування файлів у Control Expert допомагає запобігти несанкціонованим змінам некваліфікованим персоналом і підсилює захист від крадіжки інтелектуальної власності та інших зловмисних дій. Опція шифрування файлів також захищена механізмом пароля. Якщо контролер керується як частина системного проєкту, то пароль застосунку та шифрування файлів вимкнені в редакторі Control Expert і мають налаштовуватися за допомогою `Topology Manager`. 

Окрім встановлення пароля, можна шифрувати файли `.STU`, `.STA` та `.ZEF`. Функція шифрування файлів у EcoStruxure Control Expert допомагає запобігти модифікаціям та посилює захист інтелектуальної власності. Опція шифрування також захищена паролем. Якщо контролер керується в межах системного проєкту, то пароль застосунку і шифрування файлів вимикаються в редакторі EcoStruxure Control Expert і задаються через Topology Manager.

Коректний пароль повинен містити щонайменше 8 символів і включати:

- хоча б одну велику літеру,
- хоча б одну малу літеру,
- хоча б одну цифру,
- хоча б один неалфавітно-цифровий символ ($, %, &, тощо).

За замовчуванням новий застосунок (проєкт) EcoStruxure Control Expert Classic має такі характеристики:

- проєкт не захищений паролем,
- файли застосунку не зашифровані.

При створенні проєкту у діалоговому вікні Security enforcement можна:

- встановити пароль для застосунку,
- застосувати шифрування до файлів застосунку через пароль шифрування файлів.

![image-20250816194412214](C:\san\Навч посіб M340\GitVer\uk2\media\image-20250816194412214.png)

Щоб обмежити доступ до EcoStruxure Control Expert після певного часу бездіяльності, встановіть прапорець `Auto-lock` та введіть значення у полі `Minutes before lock`, щоб задати тайм-аут. Функція авто-блокування обмежує доступ до програмного інструменту EcoStruxure Control Expert після заданого часу бездіяльності. Для її активації потрібно вибрати прапорець `Auto-lock` та вказати час бездіяльності у хвилинах. Якщо функція авто-блокування увімкнена і час бездіяльності минув, з’являється діалогове вікно для введення пароля застосунку. Вікна редактора залишаються відкритими в тому ж стані, тому будь-хто може бачити вміст, але не може продовжувати роботу з EcoStruxure Control Expert. Якщо для проєкту не призначено пароля, діалогове вікно не з’являється.

Перед тим, як увімкнути опцію шифрування файлів, потрібно встановити пароль застосунку.

### Пароль для оновлення прошивки

Захист прошивки паролем допомагає запобігти небажаному доступу до прошивки модуля. Для контролерів M580 керування оновленнями прошивки залежить від версії прошивки, використаної для створення застосунку.

- Для версій прошивки раніше 4.01:
  - Оновлення прошивки здійснюється через FTP.
  - Доступ до сховища можна захистити паролем.
- Для версій прошивки 4.01 і новіших:
  - Доступ до оновлення прошивки здійснюється через HTTPS (безпечніше за FTP).
  - Доступ до оновлення прошивки обов’язково має бути захищений паролем.
  - Доступ до сховища даних та веб-сторінок захищений тим самим паролем.

Пароль чутливий до регістру та містить від 8 до 16 алфавітно-цифрових символів. Надійність пароля зростає, якщо він містить поєднання великих і малих літер, алфавітних, числових і спеціальних символів. Під час імпорту файлу ZEF пароль прошивки зберігається в модулі лише в тому випадку, якщо обрано параметр *File encryption*. Пароль можна змінити в будь-який момент.

- Значення пароля за замовчуванням у застосунку Control Expert: `fwdownload`.
- Для прошивок версії V4.01 і вище необхідно змінити пароль за замовчуванням, інакше створення застосунку Control Expert буде неможливим.
- Для версій прошивки нижчих за V4.01 це не є обов’язковим, але настійно рекомендується.

![image-20250816195600606](C:\san\Навч посіб M340\GitVer\uk2\media\image-20250816195600606.png)

### Пароль для програмного блоку, секції та підпрограми

Функція захисту програмного блоку, секції та підпрограми, коли увімкнена, використовує пароль для захисту цих елементів програми. Цю функцію можна налаштувати та викликати з екрана властивостей проєкту в офлайн-режимі. 

Це не заважає вам:

- підключатися до контролера,
- завантажувати застосунок з контролера,
- змінювати конфігурацію,
- додавати нові програмні блоки (Program Units) та/або секції,
- змінювати логіку в новій секції, яка не захищена паролем.

Щоб заблокувати секцію або програмний блок для редагування, необхідно виконати обидві умови:

1. Активувати захист на рівні проєкту (`Application`). 
2. Вибрати тип захисту в полі *Protection* для секції або програмного блоку. 

![image-20250816203118312](C:\san\Навч посіб M340\GitVer\uk2\media\image-20250816203118312.png)

### Пароль для сховища даних / веб-доступу

Захист паролем допомагає запобігти небажаному доступу до зони зберігання даних SD-карти (якщо у контролер вставлена дійсна карта). Для контролерів M580 у проєктах, створених у Control Expert:

- До версії 15.1: можна встановити парольний захист для доступу до сховища даних.
- Починаючи з версії 15.1: можна встановити парольний захист як для веб-діагностики, так і для доступу до сховища даних.

Керування сховищем даних та веб-інтерфейсом залежить від версії прошивки контролера:

- Для версій прошивки раніше 4.01:
  - Сховище даних керується через FTP.
  - Доступ до сховища можна захистити паролем.
  - Доступ до веб-сторінок захистити паролем неможливо.
- Для версій прошивки 4.01 і новіших:
  - Сховище даних керується через HTTPS (безпечніше за FTP).
  - І доступ до сховища даних, і доступ до веб-сторінок обов’язково мають бути захищені паролем.
  - Для доступу використовується один і той самий пароль.

Якщо контролер керується в межах системного проєкту, то пароль Web Diagnostic/Data Storage вимикається в редакторі EcoStruxure Control Expert і має задаватися через Topology Manager. Пароль чутливий до регістру та містить від 8 до 16 алфавітно-цифрових символів. Надійність пароля зростає, якщо він містить комбінацію великих і малих літер, алфавітних, числових і спеціальних символів. Під час імпорту файлу ZEF пароль Data Storage/Web зберігається в модулі лише у випадку, якщо вибрано опцію *File encryption*.

Пароль можна змінити будь-коли. Пароль Data Storage/Web має значення за замовчуванням у застосунку EcoStruxure Control Expert. Воно залежить від версії:

- `datadownload` — для версій EcoStruxure Control Expert раніших за 15.1
- `webuser` — для версій EcoStruxure Control Expert починаючи з 15.1

Необхідність зміни пароля залежить від версії прошивки модуля:

- Починаючи з версії прошивки 4.01 потрібно обов’язково змінити пароль Data Storage/Web, інакше побудова застосунку EcoStruxure Control Expert буде неможливою.
- Для версій прошивки нижчих за 4.01 це не є обов’язковим, але настійно рекомендується.

## Посилення захисту ПК 

Робочі станції, розташовані у диспетчерській, сильно піддаються атакам. Ті ПК, які підтримують EcoStruxure™ Control Expert або EcoStruxure™ Server Expert, необхідно захищати.

Оскільки ці застосунки працюють у середовищі Windows OS, цей розділ пропонує рекомендації щодо захисту ПК зосереджено на безпеці Windows 10.

Захист інженерної робочої станції
 Для підвищення безпеки робочої станції використовуються такі основні засоби. Для отримання детальної інформації про кожен пункт натисніть на нього:

- Зменшення поверхні атаки
- Конфігурація та перевірка політики безпеки
- Управління обліковими записами користувачів
- Управління контролем доступу
- Захист мережевих сервісів, включаючи:
  - Вимкнення протоколу віддаленого робочого столу (RDP)
  - Вимкнення LANMAN і NTLM
  - Вимкнення невикористовуваних мережевих інтерфейсних карт
  - Налаштування локального мережевого підключення
- Увімкнення або встановлення антивірусного захисту
- Систематичне управління оновленнями
- Управління резервним копіюванням
- Управління конфіденційністю
- Управління аудитом

Ця тема також містить посилання на кілька керівництв із кіберзахисту Windows 10.

Зменшення поверхні атаки
 Поверхня атаки вашої мережевої системи — це сукупність областей, де зловмисник може спробувати додати або витягти дані.

Щоб зменшити можливу поверхню атаки:

- Вимкніть усі програмні застосунки, служби та комунікаційні порти, які не використовуються.
- Вимкніть або обмежте доступ до змінних носіїв (наприклад, USB).
- Використовуйте робочу станцію лише для однієї функції (наприклад, встановіть OPC UA Server Expert і Control Expert на різних ПК).

Конфігурація та перевірка політики безпеки
 Політику безпеки Windows можна встановити через об’єкти групових політик (GPO).

Об’єкт групової політики (GPO) — це набір змін конфігурації, які можна застосувати до робочої станції ПК. Для отримання додаткової інформації про редактор локальних групових політик зверніться до керівництв з конфігурації безпеки від Центру інтернет-безпеки (CIS), наведених нижче.

GPO також можна визначати у Windows Active Directory.

Конфігурації безпеки потрібно регулярно й автоматично перевіряти.

Управління обліковими записами користувачів
 Зміна паролів за замовчуванням:

- Перед введенням в експлуатацію будь-якого нового ресурсу змініть усі паролі за замовчуванням на значення, що відповідають рівню адміністративних облікових записів.
- Вимкніть автоматичний вхід у Windows.
- Для опису параметрів паролів облікових записів Windows зверніться до керівництв з конфігурації безпеки від CIS.

Налаштування облікових записів користувачів:
 Облікові записи можуть бути визначені локально (робоча група) на окремому комп’ютері або через контролер домену Windows Active Directory, який дозволяє централізовано керувати всіма користувачами системи.

Рекомендації:

- Використовуйте стандартний індивідуальний обліковий запис користувача (без прав адміністратора) для запуску застосунків, що працюють автономно (наприклад, Control Expert).
- Використовуйте локальний системний обліковий запис для програм, які працюють як служби (наприклад, OFS UA).
- Використовуйте окремий адміністративний обліковий запис для встановлення програм та налаштування IPSec.
- Використовуйте менеджер паролів для управління паролями (наприклад, KeyPass).
- Вимкніть усі облікові записи, не пов’язані з бізнесом (наприклад, Debug accounts). (CIS control 16.8).
- Автоматично вимикайте неактивні облікові записи після певного періоду бездіяльності. (CIS control 16.9).
- Автоматично блокуйте сеанси робочої станції після стандартного періоду неактивності. (CIS control 16.11).

Управління контролем доступу
 Доступ до всієї інформації, що зберігається у файлових системах, спільних мережевих ресурсах, додатках або базах даних, повинен контролюватися. Ці заходи забезпечують принцип мінімальних привілеїв: тільки авторизовані особи можуть мати доступ і лише до тієї інформації, яка їм мінімально необхідна.

Дозволи стосуються об’єктів і можуть бути реалізовані на основі:

- об’єктів Windows Active Directory,
- доступу до файлів NTFS через дискреційні списки контролю доступу (DACLs),
- дозволів спільних папок,
- служби Remote Registry (увімкнення/вимкнення).

Привілеї — це права користувача, які не прив’язані до об’єкта, а є специфічними для машини. Їх можна керувати через групові політики, наприклад, у налаштуваннях доступу до змінних носіїв у редакторі локальної групової політики можна обмежити доступ до USB (читання або запис).

Захист мережевих сервісів
 Видаліть або вимкніть непотрібні чи невикористовувані мережеві сервіси.

Існує кілька способів вимкнути службу: через утиліту Services, шаблон безпеки, об’єкт групової політики, PowerShell, SC.exe.

Використовуйте брандмауер Windows з правилом «deny by default», яке блокує весь трафік, крім дозволених портів і сервісів.

Брандмауер:
 Брандмауер Windows потрібен для конфігурації IPSEC у Windows 10. У нових версіях ОС Windows, включаючи Windows 10, він увімкнений за замовчуванням.

Server Manager:
 Server Manager дозволяє переглядати всі залежності функцій і визначати, чи варто їх видаляти з Windows Server. Можна обирати ролі (наприклад, IIS, DNS Server) і функції (наприклад, BitLocker, .NET Framework).

Інтернет-сервер IIS – захист:

- Використовуйте мінімальну інсталяцію останньої версії.
- Налаштуйте контроль доступу (TLS та автентифікацію користувачів).
- Увімкніть журналювання та перевіряйте логи на ознаки атак.

Вимкнення SMBv1:
 SMBv1 — протокол для обміну файлами та сервісами між ПК у мережі. Він містить вразливість віддаленого виконання коду. Рекомендується вимкнути SMBv1.

Вимкнення RDP:
 Рекомендовано вимикати віддалений робочий стіл, якщо застосунок не вимагає RDP.

Кроки:

1. У Windows 10 вимкніть RDP у Computer > System Properties > Advanced System Settings.
2. На вкладці Remote зніміть галочку «Allow Remote Assistance…».
3. Виберіть «Don’t Allow Connection…».

Вимкнення LANMAN і NTLM:

1. Виконайте secpol.msc, відкрийте Local Security Policy.
2. Security Settings > Local Policies > Security Options.
3. У полі LAN Manager authentication level оберіть «Send NTLMv2 response only. Refuse LM & NTLM».
4. Позначте «Do not store LAN Manager hash value on next password change».
5. Виконайте gpupdate для збереження змін.

Вимкнення невикористовуваних мережевих карт:
 Якщо у системі 2 карти, а використовується тільки одна, іншу треба вимкнути.

Кроки:

1. Відкрити Control Panel > Network and Sharing Center > Change Adapter Settings.
2. Вимкнути непотрібне з’єднання.

Налаштування локального з’єднання:

- Вимкнути IPv6.
- Відключити всі опції, окрім QoS Packet Scheduler і IPv4.
- У налаштуваннях TCP/IP вимкнути LMHOSTS і NetBIOS.
- Дозволити File and Print Sharing.
- Використовувати тільки статичні IP, не застосовувати DHCP чи DNS.

Антивірус:
 У Windows 10 є вбудовані засоби (Defender, SmartScreen). Використовуйте їх та/або додаткове ПЗ.

- Налаштуйте регулярне оновлення антивірусних баз (CIS Control 8.2).
- Сканування змінних носіїв (CIS Control 8.4).
- Забороніть автозапуск USB (CIS Control 8.5).

Оновлення:
 Завжди встановлюйте останні стабільні оновлення ОС, драйверів, програм. Використовуйте автооновлення.

Резервне копіювання:

- Виконуйте регулярні автоматичні бекапи (CIS 10.1).
- Використовуйте образи для швидкого відновлення (CIS 10.2).
- Захищайте копії фізично або шифруванням (CIS 10.4).
- Майте принаймні одну офлайн-копію (CIS 10.5).
- Можна використовувати File History, Recovery Drive, або хмарні сервіси.

Конфіденційність:

- Відключіть від мережі системи, які не використовуються постійно, або використовуйте їх як віртуальні. (CIS 13.2).
- Використовуйте BitLocker для шифрування дисків.

Аудит:
 Переконайтеся, що локальне логування налаштоване.
