# Topology Manager

Topology Manager - це інтерфейс користувача, який відкривається під час запуску EcoStruxure Control Expert (далі — програмне забезпечення) з відповідною ліцензією. Він дозволяє проєктувати системи керування, що містять кілька контролерів, і забезпечує додаткову функціональність. 

Для відображення та/або зміни вмісту проєкту керування Topology Manager вбудовує редактор EcoStruxure Control Expert. Це спеціалізований екземпляр EcoStruxure Control Expert Classic, який відкривається під час редагування проєкту керування контролера. Деякі параметри конфігурації та команди недоступні в цих редакторах. Відповідні атрибути необхідно налаштовувати, а команди виконувати у Topology Manager.

### Керування правами доступу користувачів

Права доступу користувачів до EcoStruxure Control Expert та період дії паролів користувачів управляються за допомогою Security Editor. Для роботи з EcoStruxure Control Expert потрібно підключитися до сервера Control Expert. Щоб встановити це з’єднання, необхідно ввести ім’я користувача, створеного та активованого в централізованій базі даних безпеки Security Editor, незалежно від чинної політики входу. Якщо для цього користувача встановлено пароль, його також потрібно ввести. Надалі, якщо політика входу встановлена як Security on, mandatory login, функціональність, доступна користувачу, визначається правами, що пов’язані з профілем цього користувача.

Якщо у Security Editor увімкнено керування періодом дії пароля користувача, і пароль користувача, що увійшов у систему, закінчується через 10 днів або менше, у вікні EcoStruxure Control Expert при підключенні до сервера з’являється піктограма сповіщення. Після закінчення терміну дії пароля стають забороненими наступні дії, і відображається повідомлення:

- Вхід до EcoStruxure Control Expert або його розблокування.
- Редагування проєкту керування.

## Каталог обладнання

До системного проєкту можна додавати обладнання з каталогу, який відображається в області TOOLBOX. Обладнання згруповане за кількома типами продуктів. Кожен тип продукту містить один або кілька діапазонів продуктів.

Після того як обладнання додане до системного проєкту, ви можете:

- додати інші апаратні компоненти, які не відображаються в області TOOLBOX (наприклад, модулі контролера) та/або замінити типові компоненти (наприклад, бекплейни) шляхом редагування проєкту керування;

## Керування паралельними діями

Завдяки клієнт-серверній архітектурі EcoStruxure Control Expert кілька користувачів можуть одночасно працювати над одним і тим самим компонентом або над різними компонентами системного проєкту. Наприклад, користувач A та користувач B можуть працювати у поданні Default Physical View одного системного проєкту для розробки архітектури; або користувач A може додавати пристрої до архітектури системного проєкту, тоді як користувач B конфігурує логічні мережі та параметри зв’язку пристроїв. Ці операції може виконувати й один користувач.

У багатокористувацькому та однокористувацькому середовищах програмне забезпечення керує одночасним доступом користувачів до представлень і екранів конфігурації, щоб зберегти цілісність даних системного проєкту. У разі конфлікту програмне забезпечення може надати доступ до даних у режимі лише для читання або вимкнути певні дії. З’являються діалогові вікна, які повідомляють, чи можна редагувати дані, чи лише переглядати їх.

Користувач може заблокувати системний проєкт, щоб обмежити доступ для інших користувачів. Примітка: механізми блокування можуть також застосовуватись, коли один користувач виконує певні паралельні завдання.

Зміни, внесені до даних системного проєкту, одразу відображаються в інших екземплярах EcoStruxure Control Expert, де відкрито той самий системний проєкт.

Якщо обрану вами команду неможливо виконати, інформацію про причину можна отримати такими способами:

- діалогові вікна, що відкриваються при спробі доступу до системних даних, які використовуються або редагуються іншим користувачем;
- інформація, відображена на вкладці OPERATIONS у панелі ACTIVITIES про активність інших користувачів, підключених до того ж сервера Control Expert;
- піктограми блокування та підказки, що відображаються на вузлах контролера M580 та дочірніх елементах у вузлі Topology панелі SYSTEM PROJECT .

Якщо Security Editor відкрито на комп’ютері, який виконує роль сервера Control Expert, у підключених екземплярах EcoStruxure Control Expert відображається повідомлення (див. Toolbar Description). Воно інформує користувачів про від’єднання від сервера, якщо зміни, внесені в Security Editor, збережено. Коли ви отримуєте таке повідомлення, потрібно негайно зберегти зміни.

Якщо екземпляр EcoStruxure Control Expert від’єднано від сервера Control Expert, відкриті в цьому екземплярі редактори (наприклад, EcoStruxure Control Expert editor) автоматично закриваються без збереження, а користувач виходить із системи.

Якщо Security Editor закрито без збереження змін, з’єднання із сервером не переривається, і повідомлення зникає у підключених екземплярах EcoStruxure Control Expert.

Для додаткової інформації про Security Editor див. EcoStruxure Control Expert, Security Editor, Operation Guide.

Примітка: якщо екземпляр EcoStruxure Control Expert підключається до сервера Control Expert, а на цьому комп’ютері вже відкрито Security Editor, повідомлення відображається в екземплярі.

Після закриття редактора об’єкта цей об’єкт розблоковується та оновлюється (якщо застосовно). У наступній таблиці описано значення стилів піктограми замка, які використовуються.

Ви можете змінювати розташування пристроїв у структурі папок топології, вибравши один або кілька пристроїв і перетягнувши їх в іншу наявну топологічну папку.

### Панель ACTIVITIES  

Панель ACTIVITIES  дозволяє переглядати та відслідковувати інженерну активність. Вона містить дві вкладки:

- OPERATIONS: показує стан дій та подій.
- DETAILS: надає деталі дій, якщо вони доступні.

Можна сортувати, фільтрувати та копіювати відображену інформацію. Обидві вкладки містять функцію пошуку. Крім того, можна налаштувати порядок колонок і вибрати, які з них відображати. Вкладка OPERATIONS відображає інформацію про події на рівні EcoStruxure Control Expert та дії, виконані в системному проєкті. Також відображаються певні завдання сервера Control Expert (наприклад, вимкнення сервера).

### Керування топологічними папками, логічними мережами та фізичними поданнями

У цьому розділі описано, як керувати топологічними папками на панелі SYSTEM PROJECT. Також описано, як створювати й конфігурувати логічні мережі та фізичні подання вашого системного проєкту. Цей крок на даному етапі є необов’язковим, оскільки типово, коли ви додаєте обладнання до системного проєкту, відповідний пристрій:

- розташований у кореневій папці Topology;
- не призначений логічній мережі, але його можна призначити мережі Default Network, яка є типовою логічною мережею.

Ви можете змінювати структуру папок і конфігурацію типової логічної мережі, створювати додаткові логічні мережі, змінювати призначення пристроїв та/або створювати додаткові фізичні подання на будь-якому етапі розробки системного проєкту залежно від потреб. Примітка: коли один або кілька користувачів працюють над одним і тим самим системним проєктом (наприклад, над конфігурацією контролера, схемою мережі або властивостями пристрою), механізми блокування можуть обмежувати виконання певних паралельних дій. У цьому випадку подробиці відображаються у діалогових вікнах та/або на вкладці ACTIVITIES панелі NOTIFICATIONS.

На панелі SYSTEM PROJECT можна створювати топологічні папки двома способами:

- за допомогою контекстного меню кореневої папки або однієї з її підпапок;
- копіюванням наявних папок і вставленням їх.

Папки можна переміщати та переглядати їхні властивості на панелі PROPERTIES. 

Логічні мережі можна створювати кількома способами:

- з вузла Logical Networks на панелі SYSTEM PROJECT. Це створює нову логічну мережу з типовими параметрами;
- з інтерфейсу пристрою, що вже є у вашому системному проєкті та має щонайменше одну IP-адресу. У цьому випадку відповідний порт пристрою призначається новоствореній логічній мережі, яка відображається на панелі SYSTEM PROJECT. Використовуючи цей метод, можна конфігурувати логічну мережу під час її створення;
- за допомогою кнопки Create Logical Network на панелі інструментів LOGICAL NETWORK VIEW.

Коли ви додаєте певні модулі до контролера та застосовуєте зміни, програмне забезпечення може створити нову логічну мережу й призначити їй інтерфейс. Примітка: коли створюється логічна мережа та їй призначається інтерфейс пристрою, властивості інтерфейсу, пов’язані з логічною мережею, автоматично конфігуруються. Опис властивостей пристроїв наведено в темі про панель PROPERTIES.
