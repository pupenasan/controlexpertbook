# General Presentation of Control Expert

Control Expert надає такі мови програмування для створення користувацької програми:
 • Function Block Diagram FBD
 • Ladder Diagram (LD) language
 • Instruction List IL
 • Structured Text ST
 • Sequential Control SFC
 • Ladder Logic 984 (LL984)

Усі ці мови програмування можуть використовуватись разом в одному проєкті. Усі ці мови (крім LL984) відповідають стандарту IEC 61131-3.

Блоки, що постачаються разом із Control Expert, утворюють розширені бібліотеки блоків — від блоків для простих булевих операцій до блоків для роботи з рядками, масивами та керування складними контурами регулювання. Для зручності огляду різні блоки згруповані у бібліотеки, які, у свою чергу, поділені на сімейства. Блоки можуть використовуватись у мовах програмування FBD, LD, IL та ST.

Програму можна побудувати з таких елементів:
 • основне завдання (MAST)
 • швидке завдання (FAST) (недоступне для Momentum)
 • від одного до чотирьох допоміжних завдань (AUX) (недоступні для Modicon M340 і Momentum)
 • програмні одиниці (Program Units), які призначаються одному з визначених завдань (доступно для Modicon M580 і Modicon M340)
 • секції, які призначаються одному з визначених завдань
 • секції для обробки подій, керованих часом (Timerx, недоступно для Momentum)
 • секції для обробки подій, керованих апаратно (EVTx, недоступно для Momentum)
 • секції підпрограм (SR)

Існує один інсталяційний пакет Control Expert (.iso-файл), а версію, яку можна запустити, визначає тип ліцензії. Доступні такі версії програмного забезпечення:
 • Control Expert S
 • Control Expert L
 • Control Expert XL
 • Control Expert XL з M580 Safety

Процесори M580 Safety входять до складу додаткового модуля Safety, який доступний для версій Control Expert L та XL.

Для активації Control Expert доступні два типи ліцензій:
 • Ліцензія з прив’язкою до вузла (Node-locked license) — для одноразового використання на локальному ПК.
 • Мережева ліцензія (Floating license) — для багаторазового використання на певній кількості дозволених ПК у мережі, підключеній до серверу корпоративних ліцензій (Enterprise License Server).

Докладну інформацію щодо активації та/або реєстрації ліцензії наведено в посібнику EcoStruxure™ Control Expert, Installation Manual.

Структурне подання
 Провідник проєкту пропонує такі можливості у структурному поданні:
 • створення та видалення елементів
 • відображення символу, який показує, чи захищені секції та програмні одиниці
 • символ секції вказує мову програмування секції (у разі порожньої секції символ має сірий колір)
 • перегляд властивостей елемента
 • створення користувацьких каталогів
 • запуск різних редакторів
 • запуск функції імпорту/експорту

Функціональне подання
 Провідник проєкту пропонує такі можливості у функціональному поданні:
 • створення функціональних модулів
 • вставлення програмних одиниць, секцій, таблиць анімації тощо методом drag-and-drop із структурного подання
 • створення елементів програми (програмних одиниць, секцій)
 • перегляд властивостей елемента
 • запуск різних редакторів
 • символ секції вказує мову програмування секції та інші атрибути



## User Application and Project File Formats

Control Expert використовує чотири типи файлів для зберігання користувацьких застосунків і проєктів. Кожен тип файлу може застосовуватися відповідно до певних потреб. Типи файлів визначаються за їхнім розширенням:

-  *.STU — файл проєкту
-  *.STA — архівований файл застосунку
-  *.XEF — файл обміну застосунками
-  *.ZEF — повний файл обміну застосунками

### Файл STU

Цей тип файлу використовується для щоденної роботи. Цей формат застосовується за замовчуванням під час відкриття або збереження користувацького проєкту. Нижче наведено переваги та недоліки файлу STU:

| Переваги                                                     | Недоліки                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Проєкт можна зберегти на будь-якому етапі (узгодженому чи неузгодженому) за допомогою стандартної команди. | Незручний для передавання проєктів через дуже великий розмір файлу. |
| Збереження та відкриття проєкту відбувається швидко, оскільки вся внутрішня база даних міститься у файлі. | Несумісний при оновленні Control Expert з однієї версії на іншу. |
| Автоматичне створення файлів резервної копії (BAK)¹          |                                                              |

¹ Кожного разу, коли файл STU зберігається, автоматично створюється резервна копія з тією ж назвою, але з розширенням BAK. Змінивши розширення з BAK на STU, можна відновити стан проєкту на момент останнього збереження. Файли BAK зберігаються в тій самій папці, що й основний файл STU.

### Файл STA

Цей тип файлу використовується для архівування проєктів і може бути створений лише після того, як проєкт згенеровано. Цей тип файлу забезпечує сумісність між різними версіями Control Expert (у напрямку вперед).

Існує два способи створення файлу STA:

-  Файл STA можна створити вручну через меню File > Save Archive у головному вікні Control Expert.
-  Файл STA створюється автоматично кожного разу, коли проєкт зберігається як STU, якщо він перебуває у стані «Built».

Примітка: Автоматично створений файл STA зберігається в тій самій директорії та має ту саму назву, що й файл STU, але з доданим суфіксом “.Auto”. Якщо вже існує файл з такою назвою, він буде перезаписаний без підтвердження.
Примітка: Якщо проєкт перебуває у стані «Built», збереження STU-файлу через сервер Control Expert також створює файл STA.

Нижче наведено переваги та недоліки файлу STA:

| Переваги                                                     | Недоліки                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Швидке збереження проєкту.                                   | Може бути створений лише після генерації проєкту.            |
| Проєкти можна передавати електронною поштою або зберігати на носіях із невеликим обсягом пам’яті. | Відкриття проєкту триває довше, оскільки перед роботою файл проєкту потрібно відновити. |
| Можливість підключення в режимі Equal Online до ПЛК після відкриття проєкту у новій версії Control Expert. Додаткову інформацію див. у розділі Connection/Disconnection (див. EcoStruxure™ Control Expert, Operating Modes). |                                                              |
| Дозволяє виконувати онлайн-модифікації з ПЛК без попереднього завантаження програми до контролера. |                                                              |
| Згенерований файл STA сумісний із усіма версіями Control Expert. |                                                              |

Примітка: Щоб завантажити файл STA, створений у іншій версії Control Expert, усі функції, використані в застосунку, мають підтримуватися поточною версією.

У таблиці нижче наведено процедуру створення файлів *.STA:

| Крок | Дія                                                          |
| ---- | ------------------------------------------------------------ |
| 1    | Запустіть поточне програмне забезпечення Control Expert:     |
|      | Start > Programs > EcoStruxure Control Expert > Control Expert. |
| 2    | Відкрийте проєкт (*.STU файл):                               |
|      | 1. File > Open.                                              |
|      | 2. Виберіть проєкт (*.STU файл).                             |
|      | 3. Натисніть Open.                                           |
| 3    | Виберіть File > Save Archive (див. примітку нижче).          |
| 4    | Виберіть місце для збереження файлу. Не зберігайте файли в стандартному каталозі Schneider Electric: |
|      | C:\Program Files\Schneider Electric\Control Expert           |
|      | Файли, збережені в цьому каталозі, можуть бути видалені під час інсталяції Control Expert. |
| 5    | Натисніть Save.                                              |
| 6    | Запам’ятайте розташування файлу *.STA на комп’ютері, оскільки він знадобиться для відновлення проєкту. |

Примітка: Функція Save Archive доступна лише за умови, що:
 • Проєкт згенеровано.
 • У меню Tools > Project Settings, у розділі Upload Information, якщо обрано параметр Include, принаймні один із двох прапорців нижче має бути відмічений.

Відновлення полягає в імпорті раніше створених і збережених файлів *.STA. Файли *.STA використовуються у випадках, коли неможливо зупинити роботу ПЛК. Щоб відновити файли *.STA, виконайте такі дії для кожного проєкту:

| Крок | Дія                                                          |
| ---- | ------------------------------------------------------------ |
| 1    | Запустіть Control Expert:                                    |
|      | Start > Programs > EcoStruxure Control Expert > Control Expert. |
| 2    | Відкрийте файл *.STA через меню File > Open.                 |
|      | Тип файлу, який потрібно вибрати, — Archived Application File (STA). |
| 3    | Натисніть Open.                                              |
| 4    | Збережіть проєкт як файл *.STU.                              |

### Файл XEF

Цей тип файлу використовується для експорту проєктів у вихідному форматі XML і може бути створений на будь-якому етапі розробки проєкту. Нижче наведено переваги та недоліки файлу XEF:

| Переваги                                                     | Недоліки                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Формат XML забезпечує сумісність проєкту з будь-якою версією Control Expert. | Відкриття проєкту триває довше, оскільки перед роботою його потрібно імпортувати. |
| Середній розмір файлу.                                       | Генерація проєкту є обов’язковою для повторного створення виконуваного коду проєкту. |
| Для роботи з ПЛК необхідно повністю перебудувати проєкт і виконати завантаження до процесора. |                                                              |
| Підключення до ПЛК у режимі Equal Online для файлу XEF неможливе. Додаткову інформацію див. у розділі Connection/Disconnection (див. EcoStruxure™ Control Expert, Operating Modes). |                                                              |

### Файл ZEF

Цей тип файлу використовується для експорту проєктів разом із глобальною конфігурацією DTM і може бути створений на будь-якому етапі розробки проєкту. Детальніше про експорт та імпорт проєктів див. у розділі Import / Export (див. EcoStruxure™ Control Expert, Operating Modes). Нижче наведено переваги та недоліки файлу ZEF:

| Переваги                                                     | Недоліки                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Формат ZEF забезпечує сумісність проєкту з будь-якою версією Control Expert. | Відкриття проєкту триває довше, оскільки перед роботою його потрібно імпортувати. |
| Середній розмір файлу.                                       | Генерація проєкту є обов’язковою для повторного створення виконуваного коду проєкту. |
| Для роботи з ПЛК необхідно повністю перебудувати проєкт і виконати завантаження до процесора. |                                                              |
| Підключення до ПЛК у режимі Equal Online для файлу ZEF неможливе. Додаткову інформацію див. у розділі Connection/Disconnection (див. EcoStruxure™ Control Expert, Operating Modes). |                                                              |

Файли генеруються через меню File > Export Project

### Інформація про сумісність

Файли STU не є сумісними між різними версіями Control Expert. Щоб використовувати проєкт у різних версіях Control Expert, користувач має зберігати один із таких типів файлів:

- Архівований файл застосунку (STA): Файл STA дозволяє повторно використовувати поточний згенерований проєкт у новій версії Control Expert, установленій на комп’ютері.
- Файл обміну застосунками (ZEF): Файл ZEF слід використовувати, якщо проєкт був згенерований.

- Файл обміну застосунками (XEF): Файл XEF також використовується, якщо проєкт був згенерований.


У таблиці нижче наведено узагальнення чотирьох типів файлів:

| Тип файлу                                | STU           | STA                | XEF                  | ZEF                  |
| ---------------------------------------- | ------------- | ------------------ | -------------------- | -------------------- |
| Бінарні застосунки                       | Так           | Так                | Ні                   | Ні                   |
| Вихідні застосунки                       | Так           | Так                | Так                  | Так                  |
| Внутрішня база даних                     | Так           | Ні                 | Ні                   | Ні                   |
| Порівняльний розмір файлу                | 10 (див. (1)) | 0.03 (див. (1))    | 3                    | 3                    |
| Порівняльний час збереження              | 10            | 1.6                | 6                    | 6                    |
| Порівняльний час відкриття               | 1             | 10                 | 10                   | 10                   |
| Підключення до ПЛК у режимі Equal Online | Можливо       | Можливо            | Неможливо (див. (2)) | Неможливо (див. (2)) |
| Резервне копіювання файлу                | Можливо       | Можливо (див. (3)) | Можливо              | Можливо              |

(1) Значення наведені у відносних одиницях для порівняння.
 (2) Підключення до ПЛК у режимі Equal Online для XEF та ZEF файлів неможливе.
 (3) Для файлів STA резервна копія створюється автоматично під час збереження, якщо проєкт перебуває у стані “Built”.
